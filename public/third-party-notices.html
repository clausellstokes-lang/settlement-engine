Third-party notices

SettlementForge distributes third-party software. This page is the inventory of what we ship, who holds the copyright in it, and under which terms it reaches you.

Verified 21 August 2026, against the build branch claude/composite-r4 at 2cdb87fa. Every licence identifier below was read out of the artefact in our own repository — a file header, a bundled licence file, a package manifest, or a font’s embedded name table. None was taken on trust from an upstream project page, and none was invented. The two production-dependency elections in section 3.3 were added later, on 22 August 2026 at 19b799ce, and the packages they name were re-read at that commit rather than carried over from the verification above.

What this covers

Three populations of third-party code and data reach a browser from our origins:

  • the vendored Fantasy Map Generator fork, served from the map origin, together with the libraries vendored inside it (section 1);
  • the web fonts served from the application origin (section 2);
  • the application’s production dependency tree, whose modules the build may include in the shipped bundle (section 3).

Development-only tooling is not distributed and is out of scope. The edge functions execute server-side and convey nothing to a browser.

Section 1.4 reports TinyMCE exactly as it ships today. The disposition of that component is an open matter for the project owner and its counsel; this page reports the present state and settles nothing about it.

1.5 Libraries we distribute without a notice

Nine of the vendored files carry no copyright or licence text at all in our copy: delaunator.min.js, dropbox-sdk.min.js, flatqueue.js, indexedDB.js, jquery-ui.min.js, mapControls.min.js, objexporter.min.js, orbitControls.min.js and polylabel.min.js. Upstream each is permissive, and the licence column in section 1.2 records that upstream position; but the artefact we serve carries nothing, so a recipient of our bytes alone receives no notice. Recording that gap here is the interim measure. Restoring the per-file headers, or shipping the upstream licence files alongside them, is tracked work.

1.6 openwidget

An 829-byte upstream chat-widget loader arrived with the fork. It carries no licence text. It also carries a hard-coded organisation identifier that appears nowhere else in this repository; the fork patch that disabled it records that the identifier is the upstream author’s, so any chat opened through it would route to him rather than to us. On this branch the only reference to the file sits below an unconditional early return added by that patch, and the map origin’s content-security policy names no third-party script host, so the widget does not load. The file is nevertheless still served, which is why it is listed. Removing it is tracked work.

3.3 The two production-dependency elections

Two production packages are offered under a choice of terms, and both choices are now recorded. We elect Apache-2.0 for dompurify and the MIT licence for rgbcolor. The elections are recorded here so a recipient knows which grant we distribute under, and so the question is settled on the record rather than left to inference.

PackageVersionOffered underOur election
dompurify3.4.12the Mozilla Public Licence 2.0 or Apache-2.0 (it ships both texts)Apache-2.0
rgbcolor1.0.1the MIT licence or the alternative terms the package offers alongside itMIT

The two rows in section 1.3 were the earlier half of the same question, and these two follow the same standard: where a permissive option is offered beside a copyleft or bespoke one, the permissive option is the one we take. The disposition is the project owner’s, taken on the record; nothing here was decided quietly.

Under those elections:

  • dompurify reaches you under Apache-2.0. The package ships the full Apache-2.0 text as its own licence file, and ships the Mozilla Public Licence 2.0 text beside it. Both travel inside the package unchanged, so the option we did not take is still visible to anyone who receives it. See section 4.4.
  • rgbcolor reaches you under the MIT licence. The package ships its own licence file, which carries the MIT terms above the copyright line in the table in section 3.2 and then names the choice in its own words; the terms are the MIT terms reproduced in section 4.1, which that file’s body matches. The alternative it offers alongside is not the grant we rely on. rgbcolor reaches the tree only as an optional dependency of canvg under jspdf.

Every licence identifier and licence body named in this section was read out of the package installed from our own lock file. We use dompurify unmodified, and we redistribute both unmodified.
