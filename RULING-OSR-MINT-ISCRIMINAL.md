## WHAT IS BEING RULED
`economyStateProse.js:328` reads `isCriminal` on `incomeSources`. The observed-shape ratchet reports
it as a read of a key no writer produces. **Lane DEADREAD refused to cure it and was right.**

## THE MEASUREMENT THAT DECIDES IT
- The single writer, `economicState.js:349`, pushes `source` and `isCriminal` **in the same object
  literal**, so on generated worlds they are co-extensive: `flagOnly: 0`, `labelOnly: 0` across
  **540 generated settlements**. The read **fires on 324 of 540**.
- Deleting it kills a live lens. Re-pointing it at the label set **adds no life at all** and would
  change authored-content behaviour while overturning a documented design ruling (ODQ 771.2) and its
  pinned test.
- The instrument already agrees: `EXPLAINED_WRITER_EXEMPTIONS` carries this exact identity as
  `conditional-generator-branch` / ODQ 771.2 and bank-tags the read on every scan.

⭐ So the finding is **true and the cure is wrong**. The ratchet is reporting its corpus's reach,
not a defect — see [[an-observation-ratchet-reports-its-corpus-reach-not-the-codes-truth]].

## RULED
**Take the governed set-growing mint: add the file row and raise the A1/A7 explained-writer pin
64 → 65.** This is a CEILING RAISE and therefore a recorded chair ruling, not a lane's act and not a
`--write`. `--write` correctly refuses it ("never add a file, never raise a number"), and that
refusal is what forced this to be a decision instead of a refresh.

**Why a raise is legitimate here and almost never elsewhere:** the pin counts *explained* writers —
reads whose conditional producer is known, named and documented. Growing it does not admit an
unexplained read; it records one more explained one. The row must carry the identity, the writer's
site, and the ODQ reference, so a later reader can re-derive the explanation rather than trust it.

## FENCES
1. ⛔ **Exactly one row and exactly one increment.** 64 → 65, no more. If the mint wants to move any
   other figure, that is a different act and it stops here.
2. ⛔ **No `--write` to absorb the finding**, no hand-edit of the baseline, no deletion of the read.
3. **The mint must be executed by the governed migration path**, not by editing the pin literal in
   isolation — the file row and the pin must move in the SAME commit, because the instrument holds
   both halves to each other.
4. ⚠ **Re-derive the 324/540 and the co-extensive `flagOnly:0 / labelOnly:0` before minting.** A
   ruling built on an unverified premise is the failure this program has recorded most often; the
   figures above are the lane's, not the chair's.
