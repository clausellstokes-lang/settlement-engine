- **THE TIER FLOOR IS REAL AND IT IS `town`.** Only three catalog rows match `granar`: `Town granary` (town, `required: true`), `City granaries` (city, `required: true`), `State granary complex` (metropolis, `required: false`, `baseChance: 0.7`). **No thorp, hamlet or village can reach this pool**, which matches the block's set: *hasGranary is a TIER PROXY (every town-plus, no village-and-below)*.
- ⭐⭐ **AND THE SECOND CONDITION IS HARD TO MEET, WHICH MAKES THIS POOL'S RANGE UNUSUALLY NARROW AND UNUSUALLY SHARP.** At **town**, `Parish churches (2-5)` is `required: true, baseChance: 1`; at **city**, `Parish churches (10-30)` is `required: true, baseChance: 1`. `assembleInstitutions.js:279-281` admits a required row before it consults the category toggle (`(inst.required && !forceExclude) || (catEnabled && toggle.require)`), so **disabling the Religious category does NOT remove them.** Only an explicit per-institution `toggle.forceExclude`, a custom roster, or an imported world can. **At METROPOLIS every church-family row is optional** — `Parish churches (50-100+)` 0.8, `Great cathedral` 0.6, `Major monasteries (5-10)` 0.55, `Hospital network` 0.55 — and the granary is 0.7.
  **So the unforced generated home of this pool is the METROPOLIS**, at roughly one roll in ninety by the catalog's own chances (0.7 × 0.2 × 0.4 × 0.45 × 0.45 ≈ 0.011 before priority weighting — **this is arithmetic from the cited baseChances, not a measured census**, and the wave's own corpus sample should settle it). A town or a city reaches this pool only where a creator deliberately struck the parish rows out.
  ⭐ **The writer should take this as a gift rather than a warning.** The towns in this pool are not towns that happen to lack a hospital; they are places whose record shows a granary and not one house of faith or care in the whole roster. That is a deliberate-looking arrangement, and the face may be written as though the arrangement means something, **without saying what it means or how it came about.**
- **EVERY COUNTRY TIER, EVERY ROUTE, EVERY TERRAIN, EVERY CULTURE, EVERY POPULATION BAND within town-plus.** None is read.
- **EVERY STRESS STATE.** No key function of this block reads `config.stressTypes`. `famine` is reachable (its probability is halved by a granary, never zeroed — `stressGenerator.js:134`); so are `plague_onset`, `under_siege`, `occupied`, `indebted`, `monster_pressure` and `wartime`. **A face here prints beneath a famine banner and beneath a plague banner.** Write nothing that a famine on the same page would make absurd.
- **EVERY BADGE.** The bar beside the sentence is `scores.disaster`, which can read STRONG on a metropolis with a full state granary and CRITICAL on the same town after a siege has eaten it. **The same face prints against both.**
- ⚠ **TWO CLOCKS, AND THEY DISAGREE.** The key is a birth fact (a name in a roster, never ruin-filtered). The badge is a live fact (the pulse re-grades it every tick). A face written as a report of what this town HAS BUILT is safe against both; a face written as a report of how the town IS DOING is safe against neither.

A face must contradict no state in that range, not merely the town on this skeleton.
