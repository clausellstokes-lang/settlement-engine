## 1. What this is

Give the user-facing AI surfaces a versioned, id-free, k-anonymous **aggregate picture of how
users actually build** — which configurations co-occur, what "a gritty trade town" statistically
means in bucket-space, where each use-case gravitates — so intent inference gets sharper. The
owner's hard constraint: **the AI must not remember this data after use.** That constraint is
satisfied architecturally, not by policy: the atlas is injected per request into stateless edge
calls; there is nowhere for it to persist.

## 3. Architecture

**One new bundle, one new distillate, zero new AI surfaces.**

1. **The distillate** (`data/intentAtlas.distillate.json`, committed): generated by a
   service-role script from `analytics_daily_rollups` intent metrics + (later) the enrichment
   rider's controlled-vocabulary tags. **Enum/count cells only. k-anonymity floor: a cell
   below k=10 distinct actors is dropped at generation.** No user ids, no session ids, no
   free text, no timestamps finer than week. Versioned `atlasVersion` + generation date.
   Schema **v0.1** adds the evidence triple (`n` / `effect` / `weight`) and a top-level
   `evidence` provenance block recording the thresholds the run used — see §7.
2. **The module** (`src/domain/intentAtlas.js`, pure, lazy-only): loads the distillate,
   exposes `buildIntentAtlasSection(surfaceKey, useCaseHint)` returning a byte-stable prompt
   block (dossier-trust section, never `direction`).
3. **The bundle** (`_shared/intentAtlasBundle.js` + `.meta.json`): one `ENTRIES` row in
   `build-edge-shared.mjs`; consumed by the walled Surveyor surfaces' static prefixes
   (construct-*, custom-content, interpret-session, surveyor-autonomy) — exactly where intent
   inference happens.
4. **The schema gate** (`tests/security/intentAtlasIdFree.test.js`): walks every distillate
   cell and REDS on anything shaped like an id (uuid/email/numeric-id patterns), any string
   field not in the enum allowlist, any cell with `n < 10`. This is the "provably id-free"
   guarantee, in the spirit of the `payload_redacted` reconstruction posture.

## 4. Binding guardrails (from the M42 proposed ruling — restated as build law)

1. **Suggestion only, never engine math.** Atlas-primed inference produces *proposed buckets
   the user confirms*; confirmed buckets + seed = the world, same as ever. Aggregate data
   touching post-authoring engine behavior is queue item **G1** — separately gated,
   golden-shifting, out of scope here. (This is also mig-134's own ENDOGENEITY rule.)
2. **Id-free at generation, proven by gate** (§3.4).
3. **E-D census visibility:** the bundle import lands in surfaces already dispositioned in
   `AI_SURFACE_WALLS`; the wall test's disposition comments gain an `intentAtlas: true` note
   so the census records the data flow. No roster change (no new surface).
4. **BYOK disclosure:** the atlas block does NOT ride requests to a user's own key unless the
   key's provider `retentionClass ∈ {zero, bounded}` (the `registerProviderAdapter` posture);
   managed-call provider retention is governed by API terms — distinct from product-layer
   statelessness, and a line for the T10 legal packet + M27 consent-posture ruling.

## 7. EVIDENTIAL WEIGHTING (owner amendment 2026-07-27)

**The owner's words:** the AI may have the telemetry, provided it comes with an honest
statistical-relevance claim. Below a threshold the data is excluded; above it, the AI weighs it
scaling with confidence.

### 7.1 The mechanism

Every cell carries three numbers instead of one:

| key | meaning | range |
| --- | --- | --- |
| `n` | distinct authors behind the cell | integer, at least `MIN_N` |
| `effect` | strength and direction of the association (phi coefficient, the 2x2 case of Cramer's V) | −1.00 to +1.00 |
| `weight` | confidence weight, computed at distillation | `WEIGHT_FLOOR` to 1.00 |

`n` is a **distinct-actor** count, which serves as both the anonymity set size and the sample
size: one actor is one independent observation. Counting raw events would inflate every
statistic through pseudo-replication — one prolific author repeating a habit would read as a
population agreeing.

The weight convention, implemented by Phase B's distillation script and documented in
`src/domain/intentAtlas.js`:

```
weight = 1 − (q / FDR_Q) × (1 − WEIGHT_FLOOR),  clamped to [WEIGHT_FLOOR, 1], 2 decimals
```

where `q` is the cell's Benjamini-Hochberg corrected significance. The mapping is chosen so
that `WEIGHT_FLOOR` is exactly the weight of a cell sitting **on** the threshold (`q = FDR_Q`).
`weight >= WEIGHT_FLOOR` and `q <= FDR_Q` are therefore the same statement, which is what lets
the renderer enforce the statistic without recomputing it.

The rendered section gains a standing instruction block: scale how far a line moves your
reading by its weight, read `effect` as magnitude and `weight` as confidence, and treat a
missing line as **no evidence either way** rather than evidence against.

### 7.2 The statistic, honestly (two sentences that matter)

A p-value conflates effect size with sample size, so at a large enough `n` a meaningless
association is still "significant" — which is why `effect` and `weight` ship as two separate
numbers, so a reliably slight pattern reads as reliably slight instead of hiding behind a
confident-looking number. And because the atlas tests many bucket pairs at once, uncorrected
per-cell significance would manufacture roughly one false pattern in twenty by construction,
so significance is Benjamini-Hochberg FDR-corrected **across all cells of one generation run**,
never read per cell in isolation.

### 7.3 STRUCTURAL EXCLUSION IS THE LAW

**Cells below the floor are DROPPED at generation and never ship.** The model cannot be trusted
to ignore data on instruction, so the exclusion is structural rather than instructed. Three
layers enforce it, in this order of authority:

1. **The distiller** drops the cell. It never enters the artifact.
2. **The gate** (`tests/security/intentAtlasIdFree.test.js`) reds if a below-floor cell is
   present in the committed file at all, and pins the artifact's declared `evidence` block
   against the module's constants so a run under a laxer bar has to disagree in writing first.
3. **The renderer's belt** (`buildIntentAtlasSectionFrom`) filters again on `WEIGHT_FLOOR` and
   `MIN_N`. A belt, not the braces: a law living only inside one generation script is one bad
   script away from being a lie, and that failure would be silent, because an under-evidenced
   line reads exactly like a well-evidenced one.

### 7.4 The three constants (manager-set defaults, owner-vetoable)

Set by the manager under the 2026-07-27 delegation, frozen as `EVIDENCE_FLOOR` in
`src/domain/intentAtlas.js`, and pinned by the gate so a change cannot drift in unread:

| constant | value | what it governs |
| --- | --- | --- |
| `FDR_Q` | `0.05` | false-discovery rate across all cells of a generation run |
| `MIN_N` | `30` | distinct authors required behind a cell |
| `WEIGHT_FLOOR` | `0.25` | the weight at exactly-threshold evidence, and so the render belt |

`MIN_N` (30) is stricter than the k-anonymity floor (10) and binds in practice, but they are
**not the same constant**: k is a privacy floor, `MIN_N` is a sample floor. A ruling that lowers
`MIN_N` cannot lower k below 10, and the gate checks both separately.

### 7.5 Sequencing consequence

The activation cliff is dissolved. There is no "is there enough data yet" call to make, because
a sparse corpus self-silences: a pattern with too few authors or too weak a signal never clears
the floor, is never generated, and renders nothing. The atlas can therefore go live at launch.
**The remaining owner moment is the consent and legal disclosure line (T10 packet), which is a
policy call, not a statistics one** — the product now tells users that aggregate, id-free
population data informs AI suggestions, and that line wants owner and legal words on it.

## 8. THE SOAK PRIOR (owner ruling 2026-07-27, wave L-8a)

**The owner's ruling:** until user telemetry clears the statistical threshold, the atlas ships a
**premade prior derived from soak / generated-world data, only for the purposes of the AI.**

§7 dissolved the activation cliff but left the atlas saying nothing at all on day one, because
an empty corpus self-silences perfectly. This wave fills that silence with the one corpus that
does exist and can be regenerated on demand: the deterministic engine's own output. Every cell
it produces is honest about being that, quiet enough never to outshout a person, and retired the
moment a person disagrees.

### 8.1 What was built

| piece | what it is |
| --- | --- |
| `scripts/distill-intent-atlas.mjs` | the distiller: runs the real settlement pipeline per seed, extracts observations, computes phi / BH / weight, writes the artifact |
| `src/domain/data/intentAtlas.distillate.json` | the artifact, **92 cells** at `atlasVersion` 0.2.0 |
| `src/domain/intentAtlas.js` | `source` on the cell schema, `SOAK_WEIGHT_CAP`, `ATLAS_RENDER_CAP`, the supersession law, the provenance paragraph |
| `tests/security/intentAtlasIdFree.test.js` | the gate, extended to the source tag, the ceiling, supersession, and the provenance sentence |
| `tests/domain/intentAtlasSoakDistiller.test.js` | the committed artifact is byte-reproducible by the documented command |

### 8.2 The dimensions, and why these

A prior distilled from generated worlds can only honestly answer questions **about generated
worlds**, so every dimension pairs a **registered config key the clerk may actually emit**
against something the **pipeline produces from it**. Config-against-config would be circular
(it would encode the distiller's own sampling grid); output-against-output would not be
actionable, because no clerk can set an output.

| surface | dimension | bucket | coBucket | receipt |
| --- | --- | --- | --- | --- |
| `construct` | `settType.<axis>` | `SETT_TYPES` minus the `random` / `custom` sentinels | `CONSTRAINT_BANDS` | `configVocabulary.js` |
| `construct` | `tradeRoute.<axis>` | the six routes the wizard offers | `CONSTRAINT_BANDS` | `ConfigurationPanel.jsx` Trade Route select |
| `construct` | `monsterThreat.<axis>` | `MONSTER_THREAT_TIERS` | `CONSTRAINT_BANDS` | `data/monsterThreat.js` |
| `customContent` | `settType.institutionShelf` | settlement tiers | `INSTITUTION_GROUPINGS` | `data/categoryVocabulary.js` |

`<axis>` ranges over `CONSTRAINT_DIMENSIONS` (resilience, volatility, externalThreat,
resourcePressure). The coBucket for a construct cell is computed with
`coarseBand(deriveSystemState(settlement)[axis].value)` — **the identical call
`intentComparator.js` uses to judge a construct result** — so a line is a statement in the
clerk's own constraint vocabulary about the verdict the comparator will actually report back.

**`interpret` and `autonomy` stay silent, deliberately.** One compiles table sessions into ops
and the other composes conditions over live simulation signals; a corpus of freshly generated
settlements contains neither, so a cell on either surface would be an invention filling a slot.
The module's own rendered text promises that absence carries no information, and this is that
promise being kept. Both surfaces still render the empty string, byte for byte, as before.

**`contentProfile` is varied but not tested.** Varying it keeps the prior from being silently
specific to `grounded`; testing it would spend false-discovery denominator on a knob whose
registered effect is on content boundaries rather than on the four constraint axes.

### 8.3 The corpus

400 worlds, generated through `generateSettlementPipeline` (the entry the product calls) with an
explicit empty `customContent` blob so the run is headless. The three tested factors are drawn
**independently per world from one seeded PRNG** — not from a modular rotation, which with
factor lists sharing a divisor would make one factor a function of another and manufacture
associations that are artefacts of the sampler. At 400 worlds the smallest factor level draws
roughly 67, comfortably above `MIN_N` = 30, and the run takes about thirteen seconds, which is
what makes re-running it in review realistic.

Three **fidelity assertions** fail the run rather than report a fiction: the resolved tier, the
resolved route, and the resolved threat must each equal what was requested, so no cell can
describe a world the engine never built.

**The artifact carries no clock.** It is a pure function of its corpus, which is both the
design's no-timestamps rule obeyed at the strictest setting and the reason byte-reproduction is
checkable at all.

### 8.4 The two new laws

**SOAK_WEIGHT_CAP = 0.5** (manager-set, owner-vetoable). The largest weight a soak cell may
carry, whatever its statistic says. Applied at distillation and clamped again by the renderer's
belt; the gate reds on a committed cell above it. This is a rule about **standing, not
support**: a soak association can be perfectly real and still deserve to be quiet, because it is
evidence about the simulator and the atlas exists to describe people. The practical consequence
is that any observed cell in the upper half of the weight range outranks every prior by
construction.

**The supersession law.** When a users-cell and a soak-cell name the same
`(surface, dimension, bucket, coBucket)` key, the soak cell is **excluded outright, never
averaged**. Blending would build an echo chamber with a statistical face: the AI suggests what
the engine already produces, users confirm the suggestion because it arrived pre-endorsed,
telemetry records that confirmation as a human preference, and the next distillation reads the
engine's own prior back as evidence about people. Presence of a users-cell supersedes **even
when that users-cell is itself below the floor and renders nothing** — the question the law
answers is "has this key been observed", not "has it been observed strongly".

**ATLAS_RENDER_CAP = 12** (manager-set, owner-vetoable). Token thrift: at most twelve lines per
surface, ranked by weight, then absolute effect, then the sort keys. The second criterion is
load-bearing rather than cosmetic, because the ceiling flattens nearly every soak cell onto the
same weight and effect is what still separates them.

### 8.5 What shipped, and what it says

92 cells: **57 on `construct`, 35 on `customContent`, 0 on `interpret` and `autonomy`.** 213
cells were tested, 33 were untestable (a zero margin, so phi is undefined), none were
under-sampled. The strongest lines are also the most obviously true, which is the point of
running the machinery against a known-behaviour corpus first: `monsterThreat: heartland` travels
with a **low** external-threat band at phi +0.97, `mountain_pass` and `isolated` routes travel
with **low** resilience, and a generated `thorp` almost never carries the `Crafts` shelf
(phi -0.91).

### 8.6 Deliberately deferred, recorded

- **The render cap crowds out whole dimension families.** All 25 surviving `settType.<axis>`
  cells fall outside `construct`'s top twelve, because the `monsterThreat` and `tradeRoute`
  associations are simply stronger. That is the ranking working as specified, but the clerk's
  primary knob ends up unrepresented. A **per-dimension cap** would guarantee coverage across
  families at a slightly higher token cost. Left as specified, flagged as vetoable.
- **`tradeRouteAccess` has no exported vocabulary.** Unlike `settType`, `monsterThreat`, and the
  institution shelves, the route set exists only as `<option>` elements in the wizard and as
  bounded-string in the construct wall. The distiller spells the six routes literally and
  asserts every one survives the pipeline unchanged, which is the strongest available
  substitute; a real export would be better.
- **`--corpus` is implemented, not stubbed.** It reads
  `{ label, generatorVersion, observations: [...] }` and runs identical statistics, so a formal
  soak artifact or a reshaping of migration 134's rollups distils without a rewrite. Only the
  source tag would change, and it is one constant.
- **The soak prior is a bootstrap, not a destination.** Every cell it holds is scheduled for
  retirement by the supersession law as real telemetry arrives, key by key.
