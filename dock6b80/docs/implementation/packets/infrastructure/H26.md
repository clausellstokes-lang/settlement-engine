## 5. Exact row and tag contract

### 5.1 Numeric inventory plus sparse schema-7 `rowTags`

`inventory` keeps exactly its existing meaning and grammar: every per-file identity value
is a positive safe integer. BANK-BY-RULE metadata lives in one new top-level `rowTags` map,
never inside the numeric inventory:

```js
{
  inventory: {
    '<canonical src file>': {
      '<key> on <shape>': positiveSafeInteger,
    },
  },
  rowTags: {
    '<canonical src file>': {
      '<key> on <shape>': {
        reason: nonBlankSingleLineString,
        rule: 'explained-writer',
      },
    },
  },
}
```

`rowTags` is sparse and generated. An empty top-level map is valid if every explained row
has disappeared; an empty per-file tag row is not. Each tag has exactly `reason` and
`rule`. `reason` must equal `reason.trim()`, have length 1–240, and contain no ASCII control
character (`U+0000`–`U+001F` or `U+007F`); do not silently trim or truncate it.

At genesis, every tag reason is derived from the matching declaration's existing nonblank
`ruling`; no second hand-maintained reason map is allowed. On later deliberate growth, the
exact caller-supplied reason replaces the prior tag reason. Same-count and shrink maintenance
preserve it, and disappearance removes the tag with the numeric row. Git history is the
append-only transition trail.
