### Q5 — Determinism and seeds

**Seeds.** World seed: `plan.seed` (kept on `campaign.instantWorld.seed`); per settlement `${seed}::iw${slot}` (or `::retryN`), echoed as the dossier's `_seed`; the pulse root `worldState.rngSeed` = `world-pulse:iw::<seed>::0` on an instant realm (seed-derived, executed) but `world-pulse:<uuid>` on a hand-built one (N4-correction). Save ids are service-assigned (non-deterministic); genesis links keep the composer's provisional ids `iw::<seed>::<n>` (N21).

**Replay recipe (byte for byte).** `pastSeed = realmPast::<campaign.instantWorld.seed ?? worldState.rngSeed>`; one labelled fork per dossier event, `createPRNG(\`${pastSeed}::${nonce}::${factRef}\`)`, where `factRef = <dossier _seed>#<ordinal in yearsAgo-desc order with a type|name tie-break>` — NOT the save id (service UUIDs differ per persist) and NOT a slot (hand-built realms have none); iterate members oldest-first with an id tie-break; apply pins in `chooseOrPin` shape (a pinned fork does not draw). Executed (P4): deterministic across runs, dossiers byte-identical; with per-event forks a strike moves ONLY the struck fact, with one shared stream it moves later facts too.
