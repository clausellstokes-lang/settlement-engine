 WHY THIS EXISTS. GA4 Enhanced Measurement does NOT emit `outbound_click` for links to
 domains configured for cross-domain measurement — Google's own note on that settings
 screen says so. `efuneral.com` and `myfuneralpreplan.com` are both in the Conversion
 Linker, so **every pre-need redirect is currently unmeasured.** That is a gap, not a
 duplicate, and pre-need is one of goal 5's conversions.

 WHY A LISTENER, NOT AN OVERRIDE. One delegated capture-phase listener covers every
 destination link on every page, including the pre-need confirm inside the redirect modal,
 regardless of which component renders it. The alternative was another per-element Framer
 override — the same fragmentation that produced 14 separate Continue overrides.

 ⚠️ LIMITATION — VERIFY THIS. This catches real anchors (` `). If Framer's
 pre-need redirect modal navigates via JavaScript instead of an anchor, no click event
 is produced and this will not fire. Test it: open a pre-need redirect and confirm a
 `destination_click` appears in the dataLayer. If it does not, that one control needs a
 code override calling the same push — this listener still covers every other
 destination, so keep it either way.

 PRE-NEED IS A CONVERSION PROXY. `plan_ahead_submit` is not measurable on our side: the
 visitor completes the form on the provider's domain. A confirmed redirect is the last
 observable step, so `destination_click` with destination_system = efuneral |
 myfuneralpreplan IS the pre-need conversion signal. Mark it accordingly in GA4, and
 label it honestly in reporting — it is a hand-off, not a completed plan.

 BONUS DIMENSION. Pre-need is split across two providers, assigned per location. Same
 spend, same locations, different platform — so `destination_system` doubles as a
 provider-comparison dimension that nothing else in the stack gives you.
