## THE DEFECT (CONFIRMED by the recon at `9a8ff7280`)
`renderScribe` loops the firing tabs and POSTs each to `scribe-render`; every invocation runs the full `runCreditedCall` with its own `spend_credits('dossierProse')` (`index.ts:300-309`). Migration 202's header ("one render of a settlement's dossier costs five credits whatever it draws") and `ScribeRedrawButton`'s label ("5 credits") are false about the whole-render price: a seven-to-ten-tab render spends 35–50 credits. The free first render (`claim_free_scribe`, once per account) is consumed by the FIRST TAB. No test pins the whole-render total. The redraw is uncapped. A per-account daily cap exists nowhere; `surveyor_usage_precheck` (144) is the estate's usage governor and the Scribe does not call it.

### CAR 1 — THE RENDER TOKEN: one credited act per render, server-minted (migration `203_scribe_render_session.sql` + `index.ts` + the transport)
- A table `scribe_render_sessions(id uuid pk, user_id, save_id text, advance_seq int, rendered_for text, engine_version text, spend_id uuid null, free boolean, tabs_expected int, tabs_landed int, created_at, expires_at)` with RLS service-role only, and two SECURITY DEFINER functions: `open_scribe_render(p_user, p_save, p_seq, p_rendered_for, p_engine, p_tabs)` → `{session_id, first: boolean}` (the FIRST call for a `(user, save, seq, rendered_for)` within the TTL creates the row and returns `first: true`; later calls return the existing row with `first: false`; expired rows are replaced) and `close_scribe_render_tab(p_session)` (increments `tabs_landed`). TTL 15 minutes. The whole-render identity is the tuple the OPEN trigger already keys on (`attemptKeyOf`), never a client-supplied token.
- `scribe-render/index.ts`: after `account_is_active` and body validation, call `open_scribe_render`. If `first`, run the free-claim and `runCreditedCall` exactly as today and store `spend_id`/`free` on the session; if NOT first, SKIP the spend and the free-claim (the render is already paid) and still run the model call under the reservation/rate-limit arms (the global USD cap and the IP bucket still guard every invocation — a paid render is not a licence to be unbounded). Meter every invocation to `ai_usage_events` as before (cost is per call; the SPEND is per render). On a first-tab failure that lands nothing, the session is closed and the spend refunded as today; a later tab's failure refunds nothing (the render landed something) — say so in the docblock and pin it.
- The transport: no protocol change (the server keys the session from the body it already receives); `renderScribe` reports `charged: 1` per render in its result.
- Tests (Deno, with fake clients): a three-tab render produces ONE `spend_credits` call and ONE free-claim; the second and third tabs carry `first: false`; an expired session re-charges; two concurrent first tabs charge once (the DB function is the serialiser: assert the SQL uses `insert … on conflict do nothing` + a re-select, and pin the unique index on the tuple); the free first render covers the WHOLE render.
