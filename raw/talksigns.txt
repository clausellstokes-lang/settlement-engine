== Suggested addition: Inanimate subjects performing human actions (dropped actors) ==

I have been seeing this more and more and fighting to understand what is happening as the text reads technically correct, but just awkward. This is when AI text assigns actions to inanimate objects, or events while not mentionign or skipping the "doer" or the people who actually perform them. AI typically writes things like Lanes "go," rooms "tighten," maps "publish," an event "absorbs labor," expertise "travels," a festival "runs." The sentences are grammatically correct and read smoothly, but I have found myself wondering why this feels incorrect. The middle of the sentence is missing: a writer with direct knowledge of the subject names the actor, not the inanimate object, because they know who did the thing. Road crews close the lanes. Hotels raise rates. The city publishes the closure maps. The teams building the event book the labor.

This differs from ordinary passive voice, which at least implies an actor by saying something like "the lanes were closed." In this pattern, the object is promoted to subject and becomes the "doer." Human writers use personification and metonymy deliberately and occasionally; LLM output defaults to actor-less constructions at high density, likely because the model is compressing patterns from text rather than actually having these conversations and seeing actions that specific people take. The cumulative effect is prose in which things happen but nobody does anything, and it persists even after obvious vocabulary tells have been edited out.

Examples from some of our marketing outputs, with the actor restored in parentheses:

"Curb lanes go for weeks on either side of the event" (crews close the curb lanes, and the closures last for weeks)
"Rooms tighten and rates move" (hotels sell out and raise rates)
"The event absorbs local labor" (the teams building the event book the local labor)
"The closure maps publish in June" (the city publishes the closure maps in June)
"The festival has run indoors since 2014" (the organizers have held the festival indoors since 2014)

This pattern complements the existing entries on present-participle trailing clauses and vague attributions: all three remove a specific, checkable human actor from the sentence. Once I could understand what I was seeing, I can not un-see this! [[User:Davocados|Davocados]] ([[User talk:Davocados|talk]]) 21:40, 13 August 2026 (UTC)

== Weird table coding ==

Lately I've been seeing the use of handcoded tables that use a very particular, weird and inherently broken format I've never, ever seen before, but have now seen at least a dozen or so times this year alone.

The format (example taken from the userpage of {{noping|Reptile021}}) goes:<br>
<nowiki>{| class="wikitable plainrowheaders"</nowiki><br>
<nowiki>! Year</nowiki><br>
<nowiki>! Title</nowiki><br>
<nowiki></nowiki><br>
<nowiki>| ! Album                     |                    |</nowiki><br>
<nowiki>| --------------------------- | ------------------ |</nowiki><br>
<nowiki>| rowspan="7"                 | 2026               |</nowiki><br>
<nowiki>| "RUN IT! (Bassline Anthem)" |                    |</nowiki><br>
<nowiki>| rowspan="6"                 | ''Bass Instinct''  |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Roll That Bassline"        |                    |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Neuro Odyssey"             |                    |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Cosmic Bass Overload"      |                    |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Bassquake"                 |                    |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Bassline Madness"          |                    |</nowiki><br>
<nowiki>| -                           |                    |</nowiki><br>
<nowiki>| "Boomtown Vibes 2026"       |                    |</nowiki><br>
<nowiki>| {{N/A                       | Non-album single}} |</nowiki><br>
<nowiki>| }                           |                    |</nowiki><br>

producing a table that looks like:

{| class="wikitable plainrowheaders"
! Year
! Title

| ! Album                     |                    |
| --------------------------- | ------------------ |
| rowspan="7"                 | 2026               |
| "RUN IT! (Bassline Anthem)" |                    |
| rowspan="6"                 | ''Bass Instinct''  |
| -                           |                    |
| "Roll That Bassline"        |                    |
| -                           |                    |
| "Neuro Odyssey"             |                    |
| -                           |                    |
| "Cosmic Bass Overload"      |                    |
| -                           |                    |
| "Bassquake"                 |                    |
| -                           |                    |
| "Bassline Madness"          |                    |
| -                           |                    |
| "Boomtown Vibes 2026"       |                    |
| {{N/A                       | Non-album single}} |
|}

Needless to say, this is not a correctly coded table, and does not produce a properly working result. Note also the closing line of the code, which does not correctly close the table, thus causing any sections that come after the table to also get swallowed up as part of the table and breaking the table even further.

I've consistently come across this particular format in either the discography tables of musicians or the filmography tables of actors and filmmakers, though there are likely other examples (or different kinds of bad table code) in other contexts as well.

Bad AI code is almost certainly the explanation for this, because it's just not plausible that this many editors would just suddenly keep inventing and duplicating the ''same'' broken table-coding format independently of each other. But it doesn't seem to be documented in the main list here yet, or if it is I couldn't find it, so I wanted to bring it to other editors' attention.
