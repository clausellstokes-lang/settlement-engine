**The brief:** run every CI job outside the five `check-*` groups at the tip, using each job's own steps
from `.github/workflows/ci.yml`. Then classify each red and cure the ones that are mine. The jobs are
`deno-tests`, `determinism-hostile-locale`, `coverage-floors`, the boot smoke, `e2e` (Chromium, then the
mobile-safari pointer audit) and `performance`. The point is that the release pull request should not
find their reds one CI round at a time.

## How the jobs were run

- Each job's steps were taken from `ci.yml` and run in this container. `npm ci` ran in the lane worktree
  with Node v22.23.4, which matches `.nvmrc`.
- **Deno:** `deno@2` (2.9.6) was installed from npm into a scratch directory outside the repository. No
  package file was touched.
- **Playwright:** the pinned `@playwright/test` 1.60.0 expects `chromium-1223`, and the container has
  `chromium-1243`. Each Playwright step therefore ran through a scratch wrapper config, never committed.
  The wrapper spreads the repository's own `playwright.config.js` (or `playwright.perf.config.js`) unchanged
  and changes only three things: `launchOptions.executablePath` points to `/opt/pw-browsers/chromium`,
  and `testDir` and `webServer.cwd` are made absolute.
- Every Playwright run used `CI=1`, so one worker and the config's own retry count. Each used the job's own
  `--reporter=github,json` and `PLAYWRIGHT_JSON_OUTPUT_NAME`, with `--trace off`.
- Gates were not piped. Each command was redirected to a file and its own exit code was read.

### The cycle cause and the probe (evidence handed to BOOT-TIP, nothing committed)

- **The cause.** A sourcemap build (`vite build --sourcemap` into a scratch directory) gives byte-identical
  chunk hashes. Its source map shows exactly one source edge from eager `engine-core` into `coherence-lazy`:
  `src/domain/display/governanceAccount.js` imports `rulingChainOf` from `src/domain/dossier/powerStrata.js`.
  - `powerStrata.js` is pinned to `coherence-lazy` in `FIRSTPAINT2_LAZY_DOMAIN`.
  - The import came with OWNER-WORDS-DOSSIER item 3a (984b08948). It is already in the first parent of
    point 22.
  - That fits point 22 having made `governanceAccount.js` engine-shared.
  - No module that stays in `engine-core` imports `governanceAccount.js`.
- **The probe.** With `'/src/domain/display/governanceAccount.js'` added to `FIRSTPAINT2_LAZY_DOMAIN` locally:
  - `smoke:boot` passes: 596/596 chunks initialised, and the shell mounted 19,354 B of markup.
  - The `performance` job then runs 2 expected out of 2 in 12 s, and its runtime guard passes.
  - `verify:dist` and the first-paint byte budget were **not** run on the pin.
  - The pin was reverted in the worktree, never staged.

### The build OOM

Two `npm run build` runs exhausted Node's default heap (2,096 MB in this container). Both ran while the
12-minute coverage run shared the four cores. Run alone, two builds at the default heap exited 0, at 52 s
each. The `--mode e2e` build also exited 0 at the default heap. CI runs each job on its own runner, so this
is not a CI risk.
