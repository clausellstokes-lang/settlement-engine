### F2 — Eyes the DM shut that the server never matches, so the content is sent and drawn. CONFIRMED.

- **What a reader gets.** The field the DM hid with an eye in the panel, on the gallery page and the party link alike. The 210 page hid it. The new client takes a served payload as already veiled (`projectServedVeil` re-runs only the groupings), so nothing hides it again.
- **Cause.** The SQL card id differs from the client's `idOf`, so the stored address (`field:<kind>:<client id>:<field>`) matches no card on the server. Two causes:
  - **(a) `_gallery_veil_card_id`, event branch (lines 225–226).** `n := _gallery_veil_or(name, title, label); if n is not null …`. Like JS `a || b || c`, the three-argument `_gallery_veil_or` returns `label` even when it is falsy. The client then tests truthiness (`eventIdFor`: `if (name) …`, else `event.legacy-<hash>`); the server tests only for SQL NULL. So an event with no truthy name or title and `label: null`, `""`, `0` or `false` gets the server id `event.null`, `event.unknown`, `event.0`. The client addresses it as `event.legacy-…`. This also turns declared limit §10.1 (fail-closed anonymous events) into a leak: such an event is neither anonymous nor matched on the server. `null` and `""` survive `JSON.stringify`, so a client save can store this row.
  - **(b) `_gallery_veil_jsstr`, number branch (lines 149–152).** A non-integer prints through `float8::text`, so `1e-7` becomes `1e-07` where JS `String()` gives `1e-7`. An integer below 1e21 prints exactly, so `9007199254740993` stays as written where JS gives `9007199254740992`. Any numeric id or label part diverges: an institution's `id`, an event's `name`, conflict `parties`. `1e-7` survives `JSON.stringify`; the big integer needs a raw write.
- **Executed** (`twins.probe.mjs`). One minimal town per row. Every eye the panel offers on the card is shut through the client's own `curateModelFor` → `writeShareVeil`. Read by the real 210 client over 210 and the real 211 client over 211. Each cell gives "the secret is in": 210 response / 210 page / 211 response / 211 page; the gallery and the link read are identical:

  | Row | 210 resp | 210 page | 211 resp | 211 page |
  |---|---|---|---|---|
  | event `{label:null, description:"EVSECRET_LABELNULL"}` | yes | no | **yes** | **yes** |
  | event `{label:"", …}` | yes | no | **yes** | **yes** |
  | event `{label:0, …}` | yes | no | **yes** | **yes** |
  | event `{name:1e-7, …}` | yes | no | **yes** | **yes** |
  | institution `{id:1e-7, desc:"INSTSECRET_TINYID"}` | yes | no | **yes** | **yes** |
  | institution `{id:9007199254740993, …}` (raw write) | yes | no | **yes** | **yes** |
  | conflict `{parties:[1e-7,"x"], stakes, desc}` | yes | no | **yes** | **yes** |
  | controls that hold: event with no `label` key; institution with `label` null or `""` (two-argument `or`); relationship `from:1e-7`; tension `name:9007199254740993` (string-only reader) | yes | no | no | no |

- **Reach.** The generator writes none of these (the lane's 360-town corpus and this review's 288 rows show no page change). It takes a hand-edited, imported, custom-content or legacy record. Within that, it is a leak of hidden content.
