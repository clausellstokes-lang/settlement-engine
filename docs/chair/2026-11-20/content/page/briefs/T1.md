# T1: a tension's spare wordings, used always (brief written 2026-11-20 11:26 UTC; read BUILDER-RULES.md first)

**THE FAULT (measured by PAGE-2 on the chair's 300 towns, hxd-<size>-<i>, base 0c9069489).** A current tension prints one of
five forms: the template's present-tense `byMemory.unanchored` form where the timeline holds no event of its kind (71%), its
CANONICAL `description` where its own event is within 80 years (16.5%), the dated form (1.6%), a sentence written for the
town (6.2%: the scarcity's lead), or a spare (4.5%). The spares (`src/data/historyDescVariants.js :: HISTORY_DESC_VARIANTS`,
two a kind, in the same past-tense register as the canonical description) are used today ONLY when the canonical sentence
would repeat the town's own past event word for word (`historyGenerator.js :: apartFromOwnEvent`).

**THE CURE.** Where a selected tension's description IS its template's canonical `description` (after `tensionByMemory`:
not the unanchored form, not the dated form, not a sentence the selection wrote for the town, not a kind keyed by
migration direction), the description is chosen among `[canonical, ...HISTORY_DESC_VARIANTS[type]]` by
`pickVariant(forms, `${config._seed}::tension::${type}`)` (zero draws; a falsy seed keeps the canonical, as today). The
chosen form then goes through the SAME path the canonical goes through today (`sizedHistoryText`, `substituteNames`,
`renderHistoryTemplate` with `placedTensionTokens`), and `apartFromOwnEvent` still applies after it (a chosen form that
repeats the town's own past event word for word takes the next form that differs, as today). Token parity: a spare that
carries a token the tension's renderer cannot fill is a finding; check every spare of every kind can render.

**FILES YOU OWN.** `src/data/historyData.js` (put the choice there as a small exported draw-free function beside
`historyDescVariantsOf`: `historyGenerator.js` is code-capped, so it gets at most one call site),
`src/generators/historyGenerator.js` (that call site only), one NEW test file `tests/data/tensionSpareWordings.test.js`.

**ACCEPTANCE (red first).** (1) Over the 300 towns (`loadGenerationLawPayloads()`, then
`generateSettlementPipeline(birthConfig({ ...DEFAULT_CONFIG, settType }), null, { seed: \`hxd-${size}-${i}\`, customContent: {} })`,
SIZES from `tests/components/pageCensusWalk.shared.mjs`; a smaller sample is fine if it still reds), the tensions printed in
the canonical-anchored case show more than one form for at least one kind (red today: one form a kind). Compute the forms
from the module's exports, never quote them. (2) For a fixed seed, the same town born twice prints the same tension text
(determinism). (3) No tension's text equals its own past event's text (the COHERENCE-PRESUME law still holds). (4) Every
non-description field of every town is unchanged against the base: compare whole documents with
`history.currentTensions[*].description` masked, on at least 60 towns (10 a size). Report the share of tensions whose text moved.

**DO NOT** touch the unanchored or dated forms (T2 writes new wordings for the unanchored form), the sides (T3), or any
other kind of text.
