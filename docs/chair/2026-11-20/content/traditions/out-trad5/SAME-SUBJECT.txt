## 1. HOW A SUBJECT IS DRAWN (read only)
- genesis.js :: deriveFoundingTraditions: rite 0 (the founding core) draws its element from the foundingFit candidates
  (founding, first-landing, charter) by genesis.js :: foundingElementWeight ("let w = el.id === 'founding' ? 3 : el.id ===
  'first-landing' ? 1.5 : 1; if (el.id === 'first-landing') w += 3;" — a water place's origin is most often its landfall).
  Every LATER rite draws from the FULL pool, with replacement: "// Element (founding core: origin-era candidates; additions:
  full pool, deduped)." The dedupe is of the MOTIF, not the element: "// Reroll a few times to avoid an identical
  (element,act) motif already present." … "if (!usedMotifs.has(`${el.id}|${act.id}`)) break;" (5 attempts). No set of used
  elements exists.
- genesis.js :: elementWeight (the additions' weight): "let w = el.foundingFit ? 0.25 : 1; // origin elements rarely recur as
  additions", then "+3" where the element's terrains hold the place's terrain, "+2" where its econ holds the place's econ.
  traditionCorpus.js :: TRADITION_ELEMENTS gives first-landing terrains ['coastal','riverside'] and econ ['port','river'], so in
  a coastal port the landfall weighs 0.25+3+2 = 5.25 as an ADDITION against 1 for an unfitted element.
- VERDICT: a repeated ELEMENT is ALLOWED BY DESIGN (the code dedupes only element+act, and its own comment foresees an origin
  element recurring as an addition, "rarely"); its RATE is chance shaped by the weighting, and the terrain/econ bonus outweighs
  the 0.25 the comment calls "rarely" (first-landing is the most repeated element below). A repeated element+ACT is what the
  design refuses (5 rerolls): 0 places in either pool.
- THE GLOSS (what prints the subject): traditionDescription.js :: compose, S1 = "${lead} that ${glossText}.", with
  "const glossText = draw(glossPool, seed, `${id}#gloss`, `gloss.${element}`, facts, CRISIS_SCOPED_ELEMENTS.includes(element));"
  — a plain draw keyed on the rite alone, NOT drawTurn: unit 10's rotation (frame slots: owner, house, power, cause, payer)
  never reaches S1. traditionDescriptionTable.js :: ELEMENT_GLOSS holds 3 wordings an element (harvest 5, 3 of them not twins),
  so two rites of one element print the SAME gloss about one time in three. The whole S1 never repeats (the act's lead
  differs: element+act never repeats), which is why unit 10's bar holds and the chair still read one honoured thing twice.
