# C-prose — cold read of new defence/prose lines (TIP 9354d792a vs DEF 6e61d042a)

Rows: 2299 (482 towns). Method: every row split into sentences, the town name and digits masked; a sentence counts as
NEW for a town only if its template is absent from the same town's DEF page (2040 town×sentence pairs, 1389 templates).
156 templates print outside the 7 towns whose power structure was re-rolled at TIP (r2r-city-55, r2r-metropolis-15,
r2r-metropolis-52, r2s-infiltrated-metropolis-2, r2s-religious_conversion-metropolis-0, r2s-slave_revolt-metropolis-3,
rv5-monster_pressure-town-5). Those 7 towns hold about 1230 one-off NPC, relationship and faction sentences.
Every fact a template asserts was checked by script against the record (defenseProfile buckets, economicState.compound.inst
flags, prosperity, stressTypes, monsterThreat, powerStructure, relationships, npcs) and against the town's own page
(threat bars, Arcane Support, economics situation text) in every town where it prints. Each template was also read by eye
in the smallest town, the largest town, and a siege, famine or occupation town where it prints.
"Carried" = the same template already printed false at DEF in other towns. Scripts: /tmp/claude-0/agents/work-C-prose/.

Notes that clear whole families:
- C2 (watch only): no town in the 972-town sample has a Professional city watch without a garrison house, so no line in this
  group names "the garrison" where only a professional watch exists. hasGarrison is unchanged TIP vs DEF in every town.
- C3: hasMilitia flips to true in 37 towns (28 in this group), all with a Household levy. The catalogue describes the levy as
  "One fit adult musters from every household ... hunting bows, spears", so "armed townsfolk", "citizen militia" and
  "armed citizens" are TRUE of it.
- Institution-list rows (PDF/Foundry "Defence: City walls and gates, Garrison, Professional city watch, ..."), 326 rows,
  14 variants: only the order changed (watch now listed after garrison). Every item is in the roster. TRUE.
  The Foundry `&#39;` is the journal's HTML escaping; it renders as an apostrophe and is not a fault.
