## Method
Scripts in /tmp/claude-0/-home-user-settlement-engine/a2e70bbe-8ee3-5a4b-b408-20d6830901c8/scratchpad/helpers/H4/:
- faith.mjs: faithReadingOf/faithLinesOf over every record, written to faith.tsv. faithdump.mjs compares it with the dumps.
- trad.mjs: deriveFoundingTraditions + filterDeclared, with forge/market rows checked against the roster (trad.tsv). search.mjs runs searchDossier for the withheld traditions.
- keeper.mjs (seatKeeper), alleg.mjs (allegiance handler rule), dmview.mjs and ruling3.mjs (dmPowerViewOf faces, titles, labels, outside-house handlers), strata.mjs (seat heading), infl.mjs (NPC header counts), tens.mjs (tension relabel), pdfhouse.mjs, pdfnpc.mjs and pdfwho.mjs (PDF text scans).
- dumpcheck.mjs: cross-checks keeper, allegiance, seat, tradition and panel rows against all 1536 dumps.
- more.seeds / more.ndjson.gz: 924 extra births.

## Not read
- NPCRelCard2 reads the keeper from the store's settlement (`useStore(s=>s.settlement)`), not the settlement the card is shown in. Its sibling NPCInlineCard uses `placeSettlement || settlement`. NPC ids are role-derived and repeat across towns (e.g. npc_lord_s_reeve), so a shared/public dossier view could style another town's card. The dumps cannot settle this (the store was set); LOW risk, unverified.
- The faith rows print only on World/Faith. They appear in no PDF, Foundry or Tonight text, so no surface twin was read.
