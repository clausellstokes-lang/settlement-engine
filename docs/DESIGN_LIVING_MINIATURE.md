## §0 Thesis + the owner's three orders
Replace the landing page's sample-dossier FACSIMILE with the REAL dossier component,
scaled into the same card footprint — tabs and all, one-to-one, interactable.
Orders, binding: (1) exactness over legibility — miniature text may be tiny;
(2) FIXED WINDOW, INNER SCROLL — a long tab (Services is the named example) scrolls
WITHIN the frame; the card bottom never moves; (3) the demo IS the product — no
facsimile markup survives.

**Why this is right (recorded so nobody re-litigates):** the facsimile is a second
rendering of what a dossier looks like — a projection-as-second-truth on the most
important marketing surface, drifting every time the real dossier evolves. The
miniature deletes the drift class and converts the landing claim into proof: the
visitor pokes the actual product before creating an account.

## §2 The canonical contract — fixture v2
One fixture, one truth, two consumers:
```
export const fixture = {
  seed, weeks, engine: { generatorVersion, simulationVersion },
  config,                    // the exact forge config the CTA replays
  settlement,                // NEW: the FULL settlement object (dossier-renderable)
  voice: { narrated, receipts },  // unchanged; STOCK grounding rule unchanged
}
```
- The excerpt fields the facsimile consumed are DELETED, not kept-and-derived —
  their only consumer dies with the facsimile. Any other `fixture.*` consumer found
  at build time (grep first) migrates to deriving from `settlement`.
- `generate-landing-fixture.mjs` gains full-settlement emission. The emitted object
  is the POST-12-TICK state (the town that has lived), matching today's provenance.
- Size discipline: the full object will be large. It lives in the lazy landing
  chunk only (never eager); if the emitted JSON exceeds ~150KB raw, the script
  strips fields the dossier never renders (a DENYLIST in the script, commented,
  not silent) — never fields it does. Measured at build, recorded in the script.

## §3 Component architecture
```
LandingArtifacts.jsx
  └─ <MiniatureFrame height={FRAME_H} naturalWidth={DOSSIER_NATURAL_W}>
       └─ <Suspense fallback={<MiniatureShimmer/>}>
            └─ <LazyOutputContainer            // dynamic import AT THIS SITE
                 settlement={fixture.settlement}
                 readOnly hideHeader={false}
                 suppressNarrativeCta />
```
- **`MiniatureFrame` is a NEW generic leaf** (`src/components/home/MiniatureFrame.jsx`
  or `src/components/common/` if a second consumer is foreseeable — implementer's
  call, recorded): props `{ height, naturalWidth, children, label }`. It owns the
  scale math, the fixed window, and the focus-stop behavior. Nothing in it is
  dossier-specific — it is "any surface, behind glass, in miniature."
- `playerView` stays FALSE: the demo shows what the visitor's own forge delivers
  (the anon OWNER's view of their draft), not the fog projection. The anon-tier
  bound is a property of the GENERATION (the fixture town is within the anon
  ceiling by design), not of the mount.

## §4 The CSS contract (precise, so nobody flails)
```
.miniature-frame     { position:relative; width:100%; height:FRAME_H;
                       overflow:hidden; }          /* the glass — NEVER grows */
.miniature-scale     { width:  naturalWidth px;
                       height: calc(FRAME_H / k) px;
                       transform: scale(k); transform-origin: top left;
                       overflow-y: auto; }         /* the inner viewport */
k = measuredFrameWidth / naturalWidth              /* responsive, computed via
                                                      ResizeObserver; k re-derives
                                                      on frame resize */
```
- FRAME_H: a design token (≈ the current card's footprint), from tokens.js — the
  no-raw-color/no-raw-number lint discipline applies to this component like any.
- `naturalWidth`: pin the dossier's desktop content width as ONE exported constant
  (measure once at build; do not re-measure the child — reflow loops).
- Scroll lives on `.miniature-scale` (inside the transform): wheel/touch pass
  through transforms natively; the scrollbar renders miniaturized — accepted per
  order (1). Long tabs scroll behind the glass; the frame bottom is law.
- Nested-scroll etiquette: `overscroll-behavior: contain` on `.miniature-scale`
  so reaching the miniature's end does not yank the page.

## §5 Chunk topology + the first-paint law
- The miniature mounts inside `LandingBelowFold` (already lazy). OutputContainer
  is imported DYNAMICALLY AT THE MINIATURE SITE — never statically from any
  landing module — so the landing chunk does not swallow the dossier chunk (the
  lazy-import-reparents hazard; recorded, has bitten).
- Load trigger: on below-fold intersection (the existing pattern) or idle — never
  on first paint. `MiniatureShimmer` is a fixed-size skeleton of FRAME_H so layout
  never shifts (CLS zero by construction).
- BUILD PIN (the 5-layer *Lazy recipe, WITH the second assertion because the
  parent is itself lazy): the landing route's eager set is byte-identical with the
  miniature present; the dossier chunk loads on demand only.

## §6 THE PROMISE-PARITY PIN (the structural prevention that makes this design
## more than cosmetics — mandatory, not optional)
A new test boots the REAL forge path with the fixture's recorded `{seed, config}`
and asserts the produced settlement DIGEST-EQUALS `fixture.settlement`.
- Green ⇒ the miniature, the fixture, and the "Forge this exact town" button are
  provably ONE artifact — "Same seed, same town. Every time." becomes a TESTED
  sentence on the landing page.
- Red ⇒ generation legitimately shifted and the fixture must regenerate — the
  regen policy graduates from a script-header comment to a MACHINE SIGNAL (it
  reds in the same commit that shifts goldens, exactly like every other golden).
- The pin uses the real pipeline entry (`generateSettlementPipeline`-class, never
  a bare sub-generator — the probe-corpus hazard), JSON-round-trips the fixture
  (the alias trap), and asserts digest equality, not deep-equal prose diffing.

## §7 Interaction + inertness contract
- LIVE inside the glass: tab switching, inner scrolling, hover states, expansion
  toggles — anything that reads.
- INERT inside the glass: anything that writes or spends — save, rename, regen,
  AI verbs, share. `readOnly` should already suppress these; the pin ENUMERATES:
  mount the miniature, assert zero elements matching the write-verb roles/names
  (a DOM census against the operation vocabulary, not a hand list).
- The CTAs stay OUTSIDE the frame, unchanged: `Save to Library` and `Forge this
  exact town` act; the miniature demonstrates. No CTA inside the glass competes
  with them.

## §8 A11y architecture (real DOM, disciplined focus)
- The miniature is real DOM — strictly better than the facsimile for readers.
- FOCUS: one stop. The frame is focusable with
  `aria-label="A live miniature of a real dossier — press Enter to explore"`;
  Enter/Space moves focus INTO the miniature (its own tablist then behaves per
  the house tab discipline); Escape returns focus to the frame. Keyboard users
  never traverse an entire dossier mid-landing-page uninvited.
- The frame carries `role="group"`; the shimmer carries `aria-busy` while loading.
- The full-size path for readable text remains the product itself (Forge CTA) —
  the legibility law's "never the only path" holds because the miniature is
  decoration-plus-proof, not the sole carrier of any fact.
