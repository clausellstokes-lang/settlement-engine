## §0 Thesis + the owner's three orders
Replace the landing page's sample-dossier FACSIMILE with the REAL dossier component,
scaled into the same card footprint — tabs and all, one-to-one, interactable.
Orders, binding: (1) exactness over legibility — miniature text may be tiny;
(2) FIXED WINDOW, INNER SCROLL — a long tab (Services is the named example) scrolls
WITHIN the frame; the card bottom never moves; (3) the demo IS the product — no
facsimile markup survives.

**Why this is right (recorded so nobody re-litigates):** the facsimile is a second
rendering of what a dossier looks like — a projection-as-second-truth on the most
important marketing surface, drifting every time the real dossier evolves. The
miniature deletes the drift class and converts the landing claim into proof: the
visitor pokes the actual product before creating an account.

## §3 Component architecture
```
LandingArtifacts.jsx
  └─ <MiniatureFrame height={FRAME_H} naturalWidth={DOSSIER_NATURAL_W}>
       └─ <Suspense fallback={<MiniatureShimmer/>}>
            └─ <LazyOutputContainer            // dynamic import AT THIS SITE
                 settlement={settlementFixture.settlement}  // the LM-1a heavy module
                 readOnly hideHeader={false}
                 suppressNarrativeCta
                 demoMode />                    // the LM-2b demo contract prop
```
- **`MiniatureFrame` is a NEW generic leaf** (`src/components/home/MiniatureFrame.jsx`
  or `src/components/common/` if a second consumer is foreseeable — implementer's
  call, recorded): props `{ height, naturalWidth, children, label }`. It owns the
  scale math, the fixed window, and the focus-stop behavior. Nothing in it is
  dossier-specific — it is "any surface, behind glass, in miniature."
- `playerView` stays FALSE: the demo shows the OWNER's view of a draft, not the
  fog projection. The anon-tier bound is a property of the GENERATION (the
  fixture town is within the anon ceiling by design), not of the mount.
- **THE DEMO MOUNT CONTRACT — NEW WORK ITEM LM-2b [CORRECTED 2026-08-02
  (self-audit): §1's v1 "store-free mount" claim was false; this contract is
  the cure]. Three named pieces:**
  1. **No anonymous-visitor RPC.** `useLiveAiCostResolver` (OutputContainer.jsx:208
     → useLivePricing) fires `supabase.rpc('get_ai_pricing')` at mount. For the
     fixture mount it is gated OFF — a `demoMode` prop or provider stub; the
     marketing page issues ZERO backend reads for a visitor who merely scrolls.
     §7's side-effect census is the pin that keeps this true.
  2. **Visitor store bleed is fenced.** Store-keyed overlays (tableView /
     focusedEntity) are suppressed under the frame, so a returning visitor's
     store residue never paints inside the glass.
  3. **The tab-set truth.** The readOnly/no-saveId mount is the PUBLIC
     projection (`publicDossier`, :444): the Map tab drops (:550) and War &
     Faith presence changes (:512) versus the /create draft view the CTA
     delivers. LM-2 runs a BUILD-TIME CHECK that enumerates the ACTUAL tab set
     under the demo mount; if it differs from the /create draft view's set (the
     branches above say it will), the delta goes to the chair BEFORE LM-2
     lands — order (1) is one-to-one exactness, and a silent tab delta is not
     the implementer's to accept. (Candidate cure on file, chair rules: a
     saveId-shaped demo sentinel so `publicDossier` resolves as the draft view —
     requires a re-audit of every `publicDossier` branch first.)

## §4 The CSS contract (precise, so nobody flails)
```
.miniature-frame     { position:relative; width:100%; height:FRAME_H;
                       overflow:hidden; }          /* the glass — NEVER grows */
.miniature-scale     { width:  naturalWidth px;
                       height: calc(FRAME_H / k) px;
                       transform: scale(k); transform-origin: top left;
                       overflow-y: auto; }         /* the inner viewport */
k = measuredFrameWidth / naturalWidth              /* responsive, computed via
                                                      ResizeObserver; k re-derives
                                                      on frame resize */
```
- FRAME_H: a design token (≈ the current card's footprint), from tokens.js — the
  no-raw-color/no-raw-number lint discipline applies to this component like any.
- `naturalWidth`: pin the dossier's desktop content width as ONE exported constant
  (measure once at build; do not re-measure the child — reflow loops).
- Scroll lives on `.miniature-scale` (inside the transform): wheel/touch pass
  through transforms natively; the scrollbar renders miniaturized — accepted per
  order (1). Long tabs scroll behind the glass; the frame bottom is law.
- Nested-scroll etiquette: `overscroll-behavior: contain` on `.miniature-scale`
  so reaching the miniature's end does not yank the page.

## §6 THE PROMISE-PARITY PIN (the structural prevention that makes this design
## more than cosmetics — mandatory, not optional)

## fixture's recorded state is reached via the town's forge PLUS four neighbour

THE PIN REPLAYS THE WHOLE RECORDED PATH — forge + THE SAME 12-TICK ADVANCE the
fixture script runs — via the script's own `buildRegion` (EXPORTED; the pin and
the script share the ONE region-build function, so the replay recipe cannot
drift from the recording):
1. Boot the real store; set exactly the recorded `forge.toggles` + `forge.locks`
   (LM-1b); stub `anonAtCap`; run the region build (town + neighbours + stamps +
   graph) and the 12 ticks.
2. Assert the FORGE-STAGE digest equals the recorded `settlementAtForge` digest
   (LM-1a). This is the leg the "Forge this exact town" CTA claims — the button
   delivers the FORGE-TIME town, and this assertion makes that sentence tested.
3. Assert the post-tick settlement DIGEST-EQUALS `settlement`. This is the
   miniature's leg — the glass shows the same town after the 12 recorded weeks.
- Both legs together make the pin and the CTA claim BOTH true: the button forges
  the town; the miniature shows that town having lived the recorded weeks — the
  fixture already frames the weeks (`fixture.weeks`), and no landing copy may
  claim the button delivers the lived state.
- Green ⇒ the miniature, the fixture, and the "Forge this exact town" button are
  provably ONE artifact — "Same seed, same town. Every time." becomes a TESTED
  sentence on the landing page.
- Red ⇒ generation legitimately shifted and the fixture must regenerate — the
  regen policy graduates from a script-header comment to a MACHINE SIGNAL (it
  reds in the same commit that shifts goldens, exactly like every other golden).
- The pin uses the real pipeline entries (`generateSettlementPipeline`-class plus
  the real store action for the store-input leg, never a bare sub-generator —
  the probe-corpus hazard), JSON-round-trips the fixture (the alias trap), and
  asserts digest equality, not deep-equal prose diffing.

## §8 A11y architecture (real DOM, disciplined focus)
- The miniature is real DOM — strictly better than the facsimile for readers.
- FOCUS: one stop. The frame is focusable with
  `aria-label="A live miniature of a real dossier — press Enter to explore"`;
  Enter/Space moves focus INTO the miniature (its own tablist then behaves per
  the house tab discipline); Escape returns focus to the frame. Keyboard users
  never traverse an entire dossier mid-landing-page uninvited.
- THE MECHANISM, NAMED [CORRECTED 2026-08-02 (self-audit): v1 never said how
  the inner subtree leaves the tab order]: the scale container carries `inert`
  while unactivated — one focus stop by construction, no tabindex sweeps, no
  MutationObserver. Activation (Enter/Space on the frame, or a pointer click ON
  THE FRAME — the frame receives it, the inert subtree cannot) removes `inert`;
  Escape returns focus to the frame and re-applies it. Honest consequence,
  accepted and recorded: pointer interaction inside the glass ALSO requires
  activation first — the glass reads as glass until you knock.
- PIN the focus-scroll case: activate, arrow through the dossier tabs (the tab
  strip focuses via `getElementById('sf-tab-' + id)`, DossierTabStrip.jsx), and
  assert the frame's scrollTop AND window.scrollY are unchanged — focusing an
  element inside a transform-scaled `overflow:hidden` frame can trigger browser
  scroll-into-view and move the page.
- The frame carries `role="group"`; the shimmer carries `aria-busy` while loading.
- The full-size path for readable text remains the product itself (Forge CTA) —
  the legibility law's "never the only path" holds because the miniature is
  decoration-plus-proof, not the sole carrier of any fact.
