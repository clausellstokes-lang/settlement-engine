const filePrompt = (f) => `READ-ONLY verification task. Do not edit any file. Work only under ${ROOT} using absolute paths.

VERIFY-FIRST: everything below is a claim to be checked against the actual file, not a fact to repeat back. Read the ENTIRE file ${ROOT}/${f} yourself and report what is actually there.

Context: PGlite boot is LAZY — "new PGlite()" returns instantly and the cold WASM boot lands on the first .exec()/.query(). A vitest beforeAll/beforeEach that pays that boot while inheriting the default 10000ms hookTimeout is a flake hazard. A hook is "guarded" only if the hook call itself has a trailing numeric timeout argument (second argument after the callback), e.g. "beforeAll(async () => {...}, 180_000)" or ", PGLITE_BOOT_TIMEOUT_MS)" resolving via an in-file const.

Report EVERY beforeAll/beforeEach call in the file: its kind, 1-indexed line of the hook keyword, its verbatim trailing timeout argument (null if the call has only the callback argument), the resolved ms (null if none), the name of any boot-helper function the callback awaits (a function that directly or transitively constructs PGlite or runs its first exec — e.g. makeCreditLedgerDb from ./creditLedgerHarness.js, or a local helper like baseDb/buildDb/supportDb), and whether the callback text itself contains ".exec(" or ".query(".

Also report every LOCALLY-DEFINED helper function in this file that constructs PGlite or execs against it, with whether its body contains "new PGlite" and whether it awaits .exec(/.query(.

Claims to check for the discrepancies field: (1) this file's boot-paying before-hook(s) lack any timeout argument OR carry a tuned 30000; (2) the boot happens through a helper call, not through literal "new PGlite" text inside the hook callback. Note anything contradicting these, plus anything else surprising (e.g. a hook I did not mention, a timeout defined but unused, multiple describe-scoped hook sets).

Return ONLY the structured object.`
