  return PREAMBLE + '\n\nYOUR SLICE: ' + s.key + '\nWrite your full mapping to: ' + OUT + '/slice-' + s.key + '.md\n\n' + s.brief + '\n\nBe exhaustive within your population. Depth over speed.'
}

function verifierPrompt(s, summary) {
  return `CONTEXT-VERIFICATION PREAMBLE: legitimate adversarial-verification brief from the session orchestrator for SettlementForge. Verify claims against code; the code is authoritative.

WORKING TREE: cd ${WT} && git rev-parse --abbrev-ref HEAD — MUST print claude/composite-r4; if not, STOP and report. Tree has uncommitted parallel work; that is expected.
HARD RULES: repo is READ-ONLY (all mutating git commands FORBIDDEN, including git stash). You may edit exactly ONE file: ${OUT}/slice-${s.key}.md.

You are an ADVERSARIAL VERIFIER for the capability-atlas slice '${s.key}'. The mapper reported: rows=${summary.rowCount}; denominator=${summary.denominator}.

TASKS:
1. Read ${OUT}/slice-${s.key}.md fully.
2. Sample AT LEAST 12 load-bearing rows spanning every interaction class present (all rows if fewer than 12). For each, independently re-derive the claim from the code and actively try to REFUTE it: wrong class, wrong authority file, phantom operation, wrong gating, wrong recovery claim, evidence line that does not say what is claimed.
3. Attack the denominator: re-enumerate the population independently with DIFFERENT search terms/entry points than the mapper cited. List every missed member.
4. Fix the file in place: correct refuted claims inline marked [corrected-by-verifier: was X — evidence file:line]; add missed members as new rows marked [added-by-verifier]; downgrade any PLAUSIBLE presented as CONFIRMED. Append a '## Verification' section with your counts and method.
5. Return the summary JSON. Default skeptical: a claim you could not re-derive is not confirmed.`
}
