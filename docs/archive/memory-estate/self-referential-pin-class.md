Two confirmed instances in the capability-remediation era, both caught by adversarial verification:
1. R-3: `SAVED_SETTLEMENT_PATCH_KEYS` hand-copied into both the helper and its test — "the allowlist IS the census" proved list==list (cured by R-4's source-derived walker).
2. Owner-tail #14 (2026-07-28): `tests/domain/factionRename.test.js` measured `FACTION_RENAME_SURFACES` against its own PROBES map keyed by the module's declared paths — a surface the module never declared was invisible. Cured by DELETING the probe map and rebuilding the denominator as an independent whole-blob walk (real pipeline output, JSON-round-tripped, every string path whose value whole-word-contains a roster faction name, multi-seed).

**Why:** A pin that shares its denominator's source with the thing it pins can agree with itself while agreeing with nothing in the data. It passes forever and guards nothing — worse than no pin, because it reads as coverage.

**How to apply:** When writing (or reviewing) any coverage/census pin, ask: where does the denominator come from? If from the same module/map being pinned, rebuild it from an independent source (source scan, real pipeline output, executed census). A verifier should attempt exactly this refutation on every new walker. See also [[json-alias-trap-npcs-members]] (the fixture discipline that made instance 2's census honest).
