## §3 · THE WAVES

### pg-1 — CONTAGION-ON-ARRIVAL

**The mechanism (one sentence): a migration column dispatched FROM a settlement whose
plague front is active is stamped plague-touched at DISPATCH; at LANDING it places an
incubating record in the EXISTING epidemic ledger, and the EXISTING onset machinery —
density + trade volume + import pressure − care, now also − the pg-2 resistance —
decides whether the plague takes hold.**

Design rulings, each with its alternative recorded:

1. **Stamp at dispatch, not read at landing.** The rejected alternative (read the
   origin's CURRENT outbreak state when the column lands) is one line cheaper but wrong
   fiction twice over: a cured origin retroactively cleans a column already on the
   road, and a newly-infected origin infects a column that left clean. The stamp is the
   sickness traveling WITH the people. Cost: one OPTIONAL column field.
2. **The cargo field**: `plagueTouched` — a BAND (0..3), derived at dispatch from
   `effectiveStressorSeverity(outbreak, originId)` through banding edges housed in the
   pg tuning table (PG_TUNING, sibling of EPIDEMIC_TUNING; the display's
   `pestilenceSeverityBand` edges 0.2/0.45/0.7 are the starting derivation, cited not
   imported — display bands must not become engine inputs by reference). DROP-WHEN-EMPTY
   exactly like `travelClass` (spatial/migration.js:558): band 0 / origin-clean columns
   carry NO key ⇒ every pre-pg save and every dark world is byte-identical.
   ⚠ OWNER-GATED GRAZE, flagged not decided: this touches the persisted MigrationColumn
   shape, and ODQ §49's correction rules the column vocabulary/carry-through JOINTLY
   across POP/LG/ES at the LG sitting. pg-1's field must be tabled there (it is a
   FIELD, not a class — it does not enter the column KEY — but the carry-through
   whitelist in `columnOf` is the same choke point, and the ES-Da couplingId lesson
   says the shape refusals surface at compile, not at design).
3. **Seeding lands in the epidemic ledger, never a second system.** At the two landing
   seams (M4 `releaseMigrationArrivals`; P2 Stage 1), a landed plague-touched column
   writes an `incubating` EpidemicRecord at the destination (`sourceId` = the column's
   origin, `incubateUntil` = the landing tick — the journey WAS the incubation), gated
   by a seeded per-column fork (`plague:column:${columnKey}:${tick}`) at
   `COLUMN_SEED_CHANCE[plagueTouched]` (banded, PG_TUNING). The standard onset roll
   then runs on the EXISTING rails: care resists, refractory windows hold, the
   SPREAD_CASCADE_CAP idiom bounds it (column seedings count against a per-tick cap,
   COLUMN_SEED_CAP, PG_TUNING), fizzles leave the existing refractory. Materialization,
   news ("Plague reaches X" — the landed `plague_arrival` impactKind, with a
   column-flavoured reason line from the existing pool machinery), religious seams,
   §128 pin interplay: ALL inherited, because it IS the one stressor.
4. **Scope: the column lanes only.** The aspatial flow lane (`flow_migration`) already
   carries its influx→disease coupling (+0.14 via `DISEASE_ARCHETYPES`, cause-blind) —
   pg-1 deliberately does NOT mount there, or a plagued-origin flow would double-count
   (generic influx lift + pg seed). Recorded as covered-by-existing; the cause-blind
   nature of that lift is a candidate refinement in pg-4, not pg-1 scope.
5. **Flag conjunctions per lane, stated:** the M4 lane exists only under
   `spatialCanonVersion` (migrationActive) — and so does the epidemic ledger
   (epidemicActive), so the seams agree. The P2 lane needs `demographicsEnabled`; its
   columns ride the same spatialLedgers.migration namespace, and pg-1's P2 arm
   additionally requires the marker (no marker ⇒ no epidemic ledger ⇒ the P2 arm is
   inert by construction — state it in the acceptance file, don't let it be
   discovered). pg-1 lit + marker absent ⇒ zero writes, byte-identical.
6. **No new push driver.** Flight-from-plague already exists on the crisis lane
   (CRISIS_FLIGHT + DISPLACEMENT_STRESSORS); P2's closed five-driver push vocabulary is
   NOT widened. pg-1 is arrival-side only.

   `plagueResistance01(settlement, item, worldState)` =

   the census's three-spellings warning) ⊕ prosperity band (the EXISTING

   prosperity/order share (care already enters as `care01` — double-counting care would
   be the collapsed-diagnosis error). Dark ⇒ the term is 0 by absence ⇒ byte-identical.
   This covers the M11a front AND pg-1's column seeding (one onset truth).
   The aspatial birth gate (`diseaseOutbreakGate`) gains two mirror-rows under the flag:
   prosperity ≥ band ⇒ ×PROSPERITY_GATE_MULT (<1), order ≥ band ⇒ ×ORDER_GATE_MULT (<1)

3. **Duration (less plague time) — the stressor's decay read gains the modifier**: the
   `disease_outbreak` counterforce profile (stressorDynamics.js:235-244) gains two
   sources under the flag — `{ causal economic_capacity }` and the order read — at
   SMALL weights beside healing's 0.7/0.3 (healing stays the dominant story; the owner's

   the estate uses elsewhere — applyPatronFeeds' identity idiom). The
   counterforce's decayMultiplier and resolutionDelta then carry prosperity/order
   automatically — the "decay read gains the modifier" lands as data, not as a new code
   path. M11a's recovering-phase relax likewise gains the resistance share beside
