## §3 · THE STATE KEYS ARE TOTAL AND DETERMINISTIC, AND THE PRECEDENCE IS WRITTEN INTO THE DERIVER

The chair's first formalization note is met at block scope and stated in the annex, not only here.
Each key set is evaluated in a STATED ORDER and resolves at the FIRST key whose antecedent holds.

**THE CHAPTER'S PRINCIPLE: MOST-CONSTRAINED ANTECEDENT FIRST.** A key exists to say what is
DISTINCTIVE about this town; an antecedent almost every town satisfies distinguishes nothing while
crowding out the ones that do. So the order runs from the hardest antecedent to the easiest.

**⛔ TWO FORMALIZATION FINDINGS, BOTH RECORDED IN THE ANNEX.**

- **`BARE` CANNOT CARRY THE TIER CLAUSE THE COMPILE GAVE IT.** The draft keyed it *few of the
  above, LOW TIER*. **A tier-gated else-arm is not total:** a high-tier settlement carrying none of
  the four antecedents would resolve to NO KEY, and the block would fall silent on exactly the town
  whose empty roster is most worth remarking. `BARE` is the pure else-arm; tier stays in the receipt
  as the fact that EXPLAINS a thin roster without GATING the key.
- **`CONTESTED` OUTRANKS `ROOTED`, WHICH INVERTS THE CHAPTER'S OWN RULE, ON TRUTH-PRESERVATION.**
  By constrainedness `ROOTED` would run first (two facts against a disjunction). It is ordered the

  legitimacy reading FALSIFIES that. A precedence order exists to stop the corpus asserting what its
  own receipt contradicts, so where the two rules disagree truth-preservation governs. This is the
  ONE place in the chapter where they disagree, and it is recorded so it does not read as drift.

**THE EIGHT-CASE CAP BINDS PER BLOCK AND IS MET WITH ROOM: 5 / 4 / 4.** Confirmed by counting the

## §7 · ⛔ A DEFECT THIS LANE INTRODUCED, CAUGHT BY READING THE PROJECTION BACK, AND CURED

Recorded because it is cheap to repeat and **nothing in the tree reds on it.**

`slotsOn()` harvests EVERY brace token on the `**SLOTS:**` line and applies **no note-stripping** to
that line (unlike variant text, which `cleanText()` cleans). This lane's first draft put the slot
corrections of §6 in an italic parenthetical **on the SLOTS line**, which silently DECLARED
`workshop` on `DS-GEN-18` and `temple` on `DS-FTH-4` — the two spellings this chapter exists to
refuse.

**Why nothing caught it:** the projection contract's undeclared-slot arm counts slots **USED but not
DECLARED**, never the reverse. A declared-but-unused slot is invisible to every instrument in the
tree. It was found only by parsing the leaf back and comparing the DECLARED set against the USED set.

**Cure, and it is structural:** the corrections moved to their own lines, and the refused spellings
are now written **WITHOUT BRACES** throughout the section, because a braced mention in prose is
indistinguishable from a use under a `grep` and this file's slot register is audited that way — the
doc-agreement-pin vacuity class. Re-verified: `grep -c '{workshop}'` and `grep -c '{temple}'` over
the whole annex both return **0**, and **declared-set == used-set EXACTLY on all three blocks**,
which is stricter than the annex requires. The hazard is written into `DS-GEN-18` in the annex so
the next writer inherits it rather than re-finds it.
