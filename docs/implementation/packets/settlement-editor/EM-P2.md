### 6.2 The three classification rules — DERIVED, not authored

```
class === 'drawn'  ⟺  stepDraws > 0 AND keyMoves > 0
class === 'label'  ⟺  stepDraws === 0 AND keyMoves > 0
class === 'pure'   ⟺  keyMoves === 0
```

`class` is therefore redundant with the two counts **by design**: the static arm asserts the derivation for all 75 rows, so a hand-edited word cannot disagree with its own numbers. At this base: **drawn 28 · label 1 · pure 46**. §21.5.2's false-positive class is the `label` row and there is exactly one.

⛔ **BOTH LANDING QUESTIONS ARE MEASURED OVER THE WHOLE SAMPLE, ROW BY ROW — there is no probe row.**

- **`onRecord` answers: does THE KEY'S FINAL VALUE land on the record?** Per corpus row, the key's value in the finished context is placed against the record by the ladder below, and the three counts are tallied.
- **`producedOnRecord` answers: does THE VALUE THIS STEP PRODUCED land on the record?** Per corpus row, the same ladder is applied to the value the step's own patch left in the context at `onStep` time — so a key a LATER producer or mutator replaced reads differently here than it does in `onRecord`.

They are different claims and the register carries both, because **the re-entry family (EM-R, design §22) needs the second to know, per writer, whether what that step wrote is what the record holds.** Each triple derives its own class by the same four rules:

```
<class> === 'absent'       ⟺  <triple>.absent === rows
<class> === 'same'         ⟺  <triple>.same === rows
<class> === 'transformed'  ⟺  <triple>.transformed === rows
<class> === 'varies'       ⟺  none of the three is unanimous
<triple>.absent + <triple>.same + <triple>.transformed === rows          (always, for BOTH triples)
```

**The per-row ladder, applied identically to both comparands** (the recon's, re-executed, with one defect fixed): (1) the key is an own property of the record and its value hash matches the value under test → `same` at `record.<key>`; (2) an own property whose hash differs → `transformed` at `record.<key>`; (3) not an own property, but the value is **an object or an array** whose serialization is ≥ 12 bytes and whose hash is found elsewhere in the record at depth ≤ 4 → `same` at that path (a nested or renamed landing); (4) not found by value but the KEY NAME appears elsewhere at depth ≤ 4 → `transformed` at that first-occurrence path; (5) otherwise → `absent`.

⭐ **STEP (3) ADMITS OBJECTS AND ARRAYS ONLY, AND THAT IS A FIX, NOT A PREFERENCE.** The recon's stated intent was *"serialisations ≥ 12 bytes only, so a scalar cannot match by coincidence"* — and a byte floor does not deliver it: `"crossroads"` serializes to 12 bytes and `"mountain_pass"` to 15, so a long enum string DOES match a coincidental sibling. Measured: under the literal byte floor `resolveConfig|tradeRoute` reads `varies` (absent 58, **same 5**) because its value collided with `record.economicState.tradeAccess` in the five long-route rows; objects-only makes it **`absent` 63/63**, which is what the recon's own published verdict for that key says ("not carried — only a coincidental scalar match"). The fix removes 5 false `same` verdicts and adds none.

⛔ **THERE IS NO `producedPath`, AND THAT IS A MEASUREMENT, NOT A SIMPLIFICATION.** The chair asked for a parallel path *only if* the post-step value ever lands at a DIFFERENT path than the final one. Executed over all 63 corpus rows × all 75 register rows, counting only rows where BOTH comparands land (a `null` is an absence the `producedOnRecord` triple already reports): **0 of 75 rows have a differing landing path.** Where a step's output reaches the record at all it reaches it at the same place the final value does; what the two comparands disagree about is *whether* it reaches, never *where*. **One `recordPath` therefore serves both triples**, and A4 re-measures that zero so the field cannot quietly become needed.

**`recordPath`, exactly.** It is defined against the **FINAL** comparand: the path the key's value lands under, observed across the non-absent rows: `record.<key>` for an own property; the found path for a nested or renamed landing (spelled as a dotted path from `record`, e.g. `record.config.stressTypes`, `record.generationCoherenceReceipt.repairs`); `null` when and only when `onRecordClass === 'absent'`. Three rules the lane may not vary:

1. **Anchor `[ \t]*`, never `\s*`.** Under `/m`, `\s*` eats the preceding NEWLINES — total length is preserved but line starts are destroyed, so `^`-anchored declaration matching drifts. (The STOP's S5 rider, recorded against the model's own `codeOnly`. The model is NOT edited.)
2. **Run over `codeOnly(raw)`** — `tests/helpers/codeOnlySource.js#codeOnly`, the estate's one shared strip, imported (never re-implemented: a second spelling of a source strip is how two instruments come to disagree while both report green).
3. ⚠ **`codeOnly` BLANKS STRING CONTENTS, so the step's own name is gone from the blanked source.** Offsets are preserved, so the name is read back **from the RAW source at the same index**: the match ends on the opening quote, and the name runs to the next occurrence of that same quote character. A name that does not match `/^[A-Za-z_$][\w$]*$/` is skipped. **This is the one subtlety a build lane must not lose**, and A8's guard-the-guard case plants it.

### 6.9 ⭐ THIS REGISTER AND EM-R0a's CLASS REGISTER — measured, so neither EM-A1 nor the EM-R family has to guess

This register classes **`(step, key)` pairs**, where `key` is a **pipeline CONTEXT key**, by entropy (`drawn · label · pure`) and by record-reach (`absent · same · transformed · varies`, twice). ⭐ **THE RULE, IN ONE PARAGRAPH (written for the design to lift verbatim).** *EM-P2's Tier 1 classifies `(step, key)` rows by **HOW a value comes to be**: whether the step drew for it (`drawn`), whether it moved without a draw (`label`), or whether it is a pure function of its inputs (`pure`) — and whether what was produced reaches the record at all (`absent · same · transformed · varies`, measured twice: once for the key's FINAL value and once for what THAT step produced).
