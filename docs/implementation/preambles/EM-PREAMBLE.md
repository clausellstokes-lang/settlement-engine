## §P4 · Coupling and the reader law

- No component imports `dmLayer.js` or `registry.js` directly except through `editSlice`; no store writer is reachable from `src/components/edit/**` except the op boundary; `src/domain/edit/**` is strict-typecheck clean and imports nothing from `src/components`.
- **One generic decree adapter** in the command registry dispatches by op type — never an adapter per op type.
- **The layer is applied on write**: the saved record carries the edited values and `dmLayer` records which fields are the DM's. Every reader — the PDF view model, the prose readers, the world book — sees one record. No composed-view second truth.
- **Readers forward, never derive.** A reader that derives a value for one caller moves the corpus for another (the tier-noun lesson of 2026-09-19: a derivation inside a desk reader moved 4,214 of 72,240 manifest cells). What a surface wants, it says in its bag.
- **Exactly one writer per state**: the registry's `stage / reorder / withdraw / reopen / markApplied / revertTick` and the layer's `applyEdit`. No second path writes `decrees` or `dmLayer`.
- **One refusal site per CONDITION** (judgment 82, as revised by EM-C4a version 4's Qd, judgment 94). A reason may be returned from more than one site when each site has a DISTINCT witnessing input; what the law forbids is a SECOND ARM FOR THE SAME CONDITION, which is unreachable code an acceptance case cannot attribute. A precondition the algorithm has already established by having reached that step is stated as an INVARIANT, never re-tested into the same reason.
- **A family that shares a frozen op vocabulary SPLICES BY POSITION IN CODEPOINT ORDER**, never by trailing spread (judgment 92; `HOME_OP_TYPES` is minted by no packet). The member computes the index with the tree's own `compareCodepoint` (`src/domain/deterministicSort.js`) and writes the composed rows out in that order, because the order arm of an earlier member is what a trailing spread reds.

## §P6 · Mutant hygiene (lifted verbatim from `GR-PREAMBLE.md` §P6, with one EM amendment)

Test trust on an EM wave is proved with disposable source mutants in an isolated immutable candidate. For every mutant, in this order: prove the source bytes actually changed (a no-op plant is a STOP); require a nonzero test exit and the named acceptance title red (a red under a different title is an ambiguous mutant and a STOP); restore the exact pre-mutant SHA-256; rerun focused green. Do not run the estate-wide shared-tree sweep in a checkout that carries other lanes' work. Anti-vacuity rules: a redundant second guard subsumes the first; a count mutant on a literal goes vacuous; a fixture that mirrors the deriver can never see a dead arm; a rendered-surface negative passes when the surface never rendered; a self-referential pin proves nothing; a multi-line `// anchored:` marker counts only if its LAST line carries it, on the line immediately above the negative — ⛔ **THE LINE IMMEDIATELY ABOVE THE `expect` ITSELF, NEVER ABOVE A WRAPPED `expect`'s FIRST LINE** (2026-09-21; EM-B1c1 version 5's build red: the wrapped expect had left its own continuation line between the marker and the assertion, and the walker reads the one line above) — and a new negative assertion is not proved until the anchor walker is green. ⭐ **A MEMBER THAT ADDS A NEGATIVE ASSERTION NAMES ITS ANCHOR IN §6**, with the positive control that anchors it: the walker polices EVERY new negative of its shapes and convicts the omission at the build, under a live seal, where the cure costs a resume and a queue slot. **EM amendment:** unlike GR, an EM acceptance file under `tests/lint/` DOES owe its mutation-coverage manifest row (§P2.2). **A WRITTEN-CONTRACT arm is proved by its counterforce measured, never red-first.** An acceptance case whose assertion already holds at the base (a declaration line pinned byte-identical, a set-equality true before the edit) cannot be red before the cure; it is proved by running the arm against a planted mutant or a perturbed input that reds the named title, restoring the exact pre-mutant SHA-256, then green — and the counterforce is quoted in the receipt beside the arm (ODQ §934.47 addendum 61 item 7; EM-B1k2's A2/A5/A6 idiom).

## §P7 · Gate-reading law (lifted verbatim from `GR-PREAMBLE.md` §P7, with the estate's pause-and-resume)

Trust no exit status you did not capture in-shell. ⛔ **A RED-FIRST WHOSE LOG PRINTS NO TEST COUNT, OR `Tests no tests`, DID NOT RUN** (2026-09-22; EM-B2a3's FIX-2 cure, first cut, whose message claimed two red-firsts as executed): a file that fails to LOAD — a `vi.mock` hoisting error, a bad import, a syntax error — exits non-zero with every step red and NOT ONE TEST EXECUTED, which reads exactly like the red a red-first wants. ## §P10 · The parallel train — THE STANDING SHAPE

⭐ **THIS IS LAW, PROVEN BY EXECUTION, NOT A FORWARD POSTURE.** The probe train EM-T8 carried one member (EM-B3d) through the whole chain on its own lane branch and landed it (`7f0621fdb`, the thirteenth landing); train EM-T9 then carried FOUR members built at the same time under four seals on four lane branches and landed them as one (`e348d59b6`, the fourteenth to seventeenth landings), with one lighting refreeze, one wiring-census regeneration and one full check at its terminal. Those two shas are executed history and carry their as-of mark under §P3.5; every figure a member predicts is still its own (PACKET-PARALLEL ruling 1; ODQ §934.47 addenda 119, 124). `PACKET_STANDARD.md`'s "Train landings" states the estate-wide law; this section states what binds an EM member.

1. **ONE PROMOTION COMMIT, THEN THE LANE BRANCHES.** A train branch `em-train-<n>-<date>` is cut at the green integration tip, and ONE promotion commit on it flips N path-disjoint, mutually independent members to READY. The lane branches are cut FROM that commit, never before it: N separate placements would collide in `PACKET_MANIFEST.json`'s array tail and in `INDEX.md`'s two tables, files in no member's own manifest (judgment 72 Q1). The lane-branch pattern is `em-t<train>-<id lower-case>-<date>`. ⛔ **THE PROMOTION COMMIT IS PROVEN BEFORE THE LANE BRANCHES ARE CUT** (judgments 121 · 122 · 129, 2026-09-21, each paid for in a stopped build or an extra gate run): `git show --stat HEAD` NAMES EVERY MEMBER'S PACKET BODY — `git commit -- <dir>` never adds an UNTRACKED file, so each new body is `git add`ed by explicit path first, and a placement that committed the entry without the body stopped its build at the seal; a RE-PLACED id is UPDATED IN PLACE (status, verified base, the body, both `INDEX.md` rows), never skipped, and its manifest entry is REBUILT FROM THE PACKET'S OWN CAPSULE rather than patched, because a by-hand rebuild that kept an older version's rows put three change rows under a five-row capsule and the next pre-proof found it; `node scripts/implementation-packets.mjs validate` prints the EXPECTED READY COUNT; and the chair NAMES THE TRAIN'S BYTE-ARM HOLDER here (§P2.11).
2. **EACH MEMBER'S HEADER NAMES ITS OWN LANE BRANCH as the verified branch, at the train base's sha**, so every lane's HEAD EQUALS its verified base and the ancestry-and-substrate check returns before it diffs. A sealed build DISPATCHES on that lane branch: the capsule is keyed to the WORKTREE's git dir (`.git/worktrees/<lane>/implementation-sessions/<ID>`), so parallel lanes cannot collide on it and a "capsule already exists" deadlock is per-worktree (judgment 71, executed: exit 0, zero bytes of stderr). Nothing in the tooling requires a particular branch — it is parsed from the packet's own Markdown header and validated only as a token. ⛔ **A LANE WORKTREE IS NEVER MOVED, AND ITS BRANCH IS NEVER COMMITTED TO, AFTER ITS DISPATCH** (judgment 125 and its second facet, 2026-09-21, found on the same afternoon by the chair and then by a lane): the seal binds THREE things — the HEAD it was taken at, the BRANCH, and the BYTES OF THE WHOLE PACKET MANIFEST (`seal.authority.manifestSha256`). A fast-forward of a live lane worktree therefore refuses at `assertImplementationScope` section (e) with `sealed HEAD or branch drifted`, and ANY chair commit to a live lane branch — even a docs-only one — refuses with `implementation authority drifted`. The cure is a RE-SEAL AT THE CURRENT HEAD: the staged build is withdrawn to a patch, `implementation:dispatch --reseal` is run on the clean tree, and the patch is re-applied BYTE-IDENTICAL, proven by the `sha256` of the staged diff before and after. Never move the worktree back — that discards the commit the move was made for. The recipe's scripts are the chair's furniture and live in the kit, never in a packet.
3. **MEASURE BEFORE YOU SEAL.** A lane's FIRST act, in plain `node` and `git` with no runner, is six measurements, each a PASS or the smallest measured contradiction: (i) branch, HEAD and verified base are the three the dispatch note names; (ii) §7's path set and the capsule's `changeManifest` are SET-EQUAL; (iii) every `CREATE` target is ABSENT and every `MODIFY` / `TEST` / `REGISTER` target PRESENT at HEAD; (iv) every required symbol is found verbatim; (v) the count law (§P9(f)), run through the packet's count prover; (vi) every line-addressed register grepped for every path the member will modify (§P2.16). Any failure is a STOP BEFORE the seal. The probe earned this rule: EM-B3d sealed first and then found its prose said four `it`s where its capsule said five, and the correction cost a commit on the train branch, a fast-forward of the lane branch, a capsule rotation and a re-dispatch (judgment 71).
4. **AUTHORING OVERLAPS; THE GATE STAYS ONE HOLDER AT A TIME.** What runs in parallel is reading, measuring, plain-`node` probes, bare `npx eslint` over touched files, the edits and the red-firsts. ⚠ Contention inflates an instrument — one directory run measured 208 s uncontended and 457.68 s with three lanes on the shared tier — so a train's wall clock is priced on the CONTENDED figure or it is a fiction.
5. **A LANE RUNS NO GATED LINE ITSELF AND COMMITS NOTHING.** It writes ONE gate script whose every vitest line goes through `sh scripts/gate-mutex.sh --run -- …`, with one row per step in a `records.tsv` (step · expected zero or nonzero · actual exit · log · what it proves), each exit captured from the command itself and never piped, the verdict computed in a plain loop before any `tee`, and the script's own exit non-zero on any unexpected result; the browser suite (§P2.15) goes in its own script. It then STAGES exactly its §7 paths by explicit path — never `git add -A`, `-u` or `.` — writes its commit message to its scratch and ENDS. The chair's one queue runs the script and, on green, commits the staged index on the LANE'S OWN branch by explicit pathspec under the lane's message. ⛔ **A LANE RE-SEALS ONLY WHILE ITS BUILD IS UNCOMMITTED** (judgment 131, 2026-09-21): once the chair has committed the staged index, the build's own paths are committed substrate — a CREATE target now EXISTS and a declared target has MOVED since the verified base — so `--reseal` refuses (`verified-base descendant changed declared substrate`), and a new version needs the lane branch REWOUND to its last packet commit, the version re-applied there, a fresh seal, and the build re-staged byte-equal. ⭐ **AND A CURE MADE AFTER THAT COMMIT IS COMMITTED ON TOP OF THE BUILD COMMIT** (judgment 141, 2026-09-22), as a MODIFY of the file the build created: a cure cut from the REWOUND seal head is an ADD of the whole file and reaches the train as an add/add conflict, resolvable only by taking the cure's blob and proving it byte-equal to the lane commit's. The rewind recipe holds for MODIFY paths; a CREATE path's cure sits ABOVE the build. Neither act is the lane's: it still commits nothing. A lane NEVER regenerates a shared register: not the wiring census, not the lighting refreeze, not the observed-shape register's `--write`, not any golden or refreeze door.
